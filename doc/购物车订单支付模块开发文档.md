## 1. 模块概述

### 1.1 模块定位

购物车、订单、支付是 agsell 系统的核心交易模块，共同构成完整的购物闭环：

```
浏览商品 → 加入购物车 → 确认订单 → 模拟支付 → 管理员发货 → 确认收货 → 评价
   ↑                                                                  ↓
   └────────────────── 返回首页/分类页 ←──────────────────────────────┘
```

- **购物车模块**：临时商品容器，支持增删改查、数量调整、全选结算
- **订单模块**：交易核心，承载商品快照、地址信息、状态流转
- **支付模块**：模拟支付流程（预留真实支付接口）

## 3. 核心业务流程

### 3.1 购物流程

```
用户登录
    │
    ▼
浏览商品 → 选择规格 → 加入购物车
    │
    ▼
购物车 → 选择商品 → 确认地址 → 提交订单
    │
    ▼
创建订单（待付款）→ 模拟支付 → 支付成功 → 订单状态变更为待发货
    │
    ▼
管理员后台处理订单 → 填写物流 → 发货 → 订单状态变更为待收货
    │
    ▼
用户确认收货 → 订单状态变更为已完成
    │
    ▼
用户评价（可选）
```

### 3.2 订单状态流转

```
          支付成功                  管理员发货               用户确认收货
[待付款] ──────────→ [待发货] ──────────→ [待收货] ──────────→ [已完成]
    │                    │                     │
    │ 用户取消/超时      │ 售后申请            │ 售后申请
    ▼                    ▼                     ▼
[已取消]              [售后中] ───────→ [售后完成/关闭]
```

| 状态码 | 状态名 | 说明 |
|:------:|--------|------|
| 0 | 待付款 | 订单创建成功，等待支付 |
| 1 | 待发货 | 支付成功，等待管理员发货 |
| 2 | 待收货 | 管理员已发货，等待用户确认 |
| 3 | 已完成 | 用户确认收货，交易完成 |
| 4 | 已取消 | 用户主动取消或超时未支付 |
| 5 | 售后中 | 用户申请售后，等待处理 |

### 3.3 订单号生成规则

- 格式：`AGS` + 16 位时间戳 + 6 位随机数
- 示例：`AGS20260826134523001234`
- 唯一性保证：数据库 UNIQUE 约束

## 4. 数据模型设计

### 4.1 购物车表 `cart`

| 字段 | 类型 | 长度 | 约束 | 默认值 | 说明 |
|------|------|------|------|--------|------|
| id | BIGINT | — | PK, AUTO_INCREMENT | — | 主键 |
| user_id | BIGINT | — | NOT NULL, INDEX | — | 用户 ID |
| product_id | BIGINT | — | NOT NULL | — | 商品 ID |
| spec_id | BIGINT | — | — | NULL | 规格 ID（多规格商品） |
| quantity | INT | — | NOT NULL | 1 | 购买数量 |
| selected | TINYINT | — | NOT NULL | 1 | 是否选中 0=否 1=是 |
| create_time | DATETIME | — | NOT NULL | CURRENT_TIMESTAMP | 创建时间 |
| update_time | DATETIME | — | — | NULL | 更新时间 |

**索引设计：**
- `idx_user_id`: INDEX `idx_user_id` (`user_id`)
- `idx_product_id`: INDEX `idx_product_id` (`product_id`)
- 联合唯一：`(user_id, product_id, spec_id)` 防止重复添加

**业务规则：**
- 同一商品+规格只能有一条记录，添加时更新数量而非新增
- 删除商品时不物理删除，仅逻辑删除（如需支持软删除可加 `deleted` 字段）
- 商品下架后购物车中对应条目标记为失效（可选）

## 6. 接口详细设计

### 6.1 购物车接口（`/api/cart`）

#### 6.1.1 加入购物车

```http
POST /api/cart/add
Content-Type: application/json
Authorization: Bearer {token}

Request Body:
{
  "productId": 1,
  "specId": 2,
  "quantity": 1
}

Response 200:
{
  "code": 0,
  "message": "ok",
  "data": null
}
```

**业务逻辑：**
1. 校验商品是否存在且上架
2. 若指定了 specId，校验规格是否存在且库存充足
3. 查询购物车中是否已有相同商品+规格记录
4. 若存在则更新数量（累加），不存在则新增
5. 校验总数量不超过库存

**参数校验：**
- productId 为空 → `PARAMS_ERROR`
- 商品不存在/已下架 → `NOT_FOUND_ERROR`
- 数量 ≤ 0 → `PARAMS_ERROR`
- 数量超过库存 → `PARAMS_ERROR`

**鉴权要求：** 必须登录

### 6.2 用户端订单接口（`/api/order`）

#### 6.2.1 提交订单（从购物车）

```http
POST /api/order/create
Content-Type: application/json
Authorization: Bearer {token}

Request Body:
{
  "addressId": 1,
  "remark": "请尽快发货",
  "cartItemIds": [1, 2, 3]
}

Response 200:
{
  "code": 0,
  "message": "ok",
  "data": {
    "orderNo": "AGS20260826134523001234",
    "payAmount": 79.80,
    "totalAmount": 79.80,
    "freight": 0.00,
    "status": 0,
    "createTime": "2026-08-26T13:45:23"
  }
}
```

**业务逻辑：**
1. 校验收货地址归属当前用户
2. 校验购物车选中的条目存在且归属当前用户
3. 批量校验库存充足
4. 生成订单号
5. 插入订单表（status=0 待付款）
6. 插入订单明细表（快照商品信息）
7. 清空购物车中选中的条目
8. 返回订单信息

**校验失败返回：**
- 地址不存在 → `NOT_FOUND_ERROR`
- 商品不存在/已下架 → `NOT_FOUND_ERROR`
- 库存不足 → `OPERATION_ERROR`

**鉴权要求：** 必须登录

---

## 7. 核心业务逻辑

### 7.1 订单创建流程

```java
@Transactional
public OrderCreateVO createOrder(OrderCreateRequest request) {
    Long userId = BaseContext.getCurrentId();

    // 1. 校验收货地址
    SysUserAddress address = addressService.getById(request.getAddressId());
    ThrowUtils.throwIf(address == null || !address.getUserId().equals(userId),
            ErrorCode.NOT_FOUND_ERROR, "地址不存在");

    // 2. 查询购物车选中商品
    List<Cart> cartItems = cartMapper.selectList(
        new LambdaQueryWrapper<Cart>()
            .eq(Cart::getUserId, userId)
            .eq(Cart::getSelected, 1)
            .in(Cart::getId, request.getCartItemIds())
    );
    ThrowUtils.throwIf(cartItems.isEmpty(), ErrorCode.PARAMS_ERROR, "请选择要结算的商品");

    // 3. 校验商品库存并计算总金额
    BigDecimal totalAmount = BigDecimal.ZERO;
    List<OrderItem> orderItems = new ArrayList<>();
    for (Cart cartItem : cartItems) {
        Product product = productMapper.selectById(cartItem.getProductId());
        ThrowUtils.throwIf(product == null || product.getStatus() != 1,
                ErrorCode.NOT_FOUND_ERROR, "商品已下架");

        ProductSpec spec = cartItem.getSpecId() != null
            ? specMapper.selectById(cartItem.getSpecId()) : null;
        ThrowUtils.throwIf(spec == null && cartItem.getSpecId() != null,
                ErrorCode.NOT_FOUND_ERROR, "规格不存在");

        // 校验库存
        int requiredStock = spec != null ? cartItem.getQuantity() : cartItem.getQuantity();
        int availableStock = spec != null ? spec.getStock() : product.getStock();
        ThrowUtils.throwIf(requiredStock > availableStock,
                ErrorCode.OPERATION_ERROR, String.format("商品 %s 库存不足", product.getName()));

        BigDecimal price = spec != null ? spec.getPrice() : product.getPrice();
        BigDecimal subtotal = price.multiply(BigDecimal.valueOf(cartItem.getQuantity()));
        totalAmount = totalAmount.add(subtotal);

        // 构建订单明细快照
        OrderItem item = new OrderItem();
        item.setProductId(product.getId());
        item.setProductName(product.getName());
        item.setProductImage(product.getMainImage());
        item.setSpecName(spec != null ? spec.getSpecName() : null);
        item.setPrice(price);
        item.setQuantity(cartItem.getQuantity());
        item.setSubtotal(subtotal);
        orderItems.add(item);
    }

    // 4. 生成订单
    String orderNo = generateOrderNo();
    Order order = new Order();
    order.setOrderNo(orderNo);
    order.setUserId(userId);
    order.setTotalAmount(totalAmount);
    order.setFreight(BigDecimal.ZERO);
    order.setDiscount(BigDecimal.ZERO);
    order.setPayAmount(totalAmount);
    order.setStatus(0); // 待付款
    order.setAddressId(address.getId());
    order.setReceiver(address.getReceiver());
    order.setPhone(address.getPhone());
    order.setAddress(address.getProvince() + address.getCity()
            + address.getDistrict() + address.getDetail());
    order.setRemark(request.getRemark());
    orderMapper.insert(order);

    // 5. 保存订单明细
    orderItems.forEach(item -> item.setOrderId(order.getId()));
    orderItemMapper.insert(orderItems);

    // 6. 清空购物车选中商品
    cartMapper.delete(new LambdaQueryWrapper<Cart>()
            .eq(Cart::getUserId, userId)
            .in(Cart::getId, request.getCartItemIds()));

    // 7. 返回订单信息
    OrderCreateVO vo = new OrderCreateVO();
    vo.setOrderNo(orderNo);
    vo.setPayAmount(totalAmount);
    vo.setTotalAmount(totalAmount);
    vo.setStatus(0);
    vo.setCreateTime(order.getCreateTime());
    return vo;
}
```

### 7.2 订单号生成

```java
private String generateOrderNo() {
    // 格式: AGS + yyyyMMddHHmmss + 6位随机数
    String timestamp = LocalDateTime.now().format(DateTimeFormatter.ofPattern("yyyyMMddHHmmss"));
    int random = (int) (Math.random() * 1000000);
    return String.format("AGS%s%06d", timestamp, random);
}
```

@Transactional
public void createPayment(String orderNo, Integer payType) {
    Long userId = BaseContext.getCurrentId();

    // 0. 校验支付方式：1=支付宝 2=微信支付，缺省按支付宝处理
    int channel = payType == null ? 1 : payType;
    ThrowUtils.throwIf(channel != 1 && channel != 2,
            ErrorCode.PARAMS_ERROR, "不支持的支付方式");

    // 1. 查询订单
    Order order = orderMapper.selectOne(new LambdaQueryWrapper<Order>()
            .eq(Order::getOrderNo, orderNo)
            .eq(Order::getUserId, userId));
    ThrowUtils.throwIf(order == null, ErrorCode.NOT_FOUND_ERROR, "订单不存在");

    // 2. 校验订单状态
    ThrowUtils.throwIf(order.getStatus() != 0,
            ErrorCode.OPERATION_ERROR, "订单状态异常，无法支付");

    // 3. 更新订单状态，记录所选支付方式
    Order update = new Order();
    update.setId(order.getId());
    update.setStatus(1); // 待发货
    update.setPayType(channel); // 1=支付宝 2=微信支付
    update.setPayTime(LocalDateTime.now());
    orderMapper.updateById(update);
}

@Transactional
public void confirmReceive(String orderNo) {
    Long userId = BaseContext.getCurrentId();

    Order order = orderMapper.selectOne(new LambdaQueryWrapper<Order>()
            .eq(Order::getOrderNo, orderNo)
            .eq(Order::getUserId, userId));
    ThrowUtils.throwIf(order == null, ErrorCode.NOT_FOUND_ERROR, "订单不存在");
    ThrowUtils.throwIf(order.getStatus() != 2,
            ErrorCode.OPERATION_ERROR, "订单状态异常，无法确认收货");

    // 更新订单状态
    Order update = new Order();
    update.setId(order.getId());
    update.setStatus(3); // 已完成
    update.setReceiveTime(LocalDateTime.now());
    orderMapper.updateById(update);

    // 增加商品销量
    List<OrderItem> items = orderItemMapper.selectList(
            new LambdaQueryWrapper<OrderItem>().eq(OrderItem::getOrderId, order.getId()));
    for (OrderItem item : items) {
        Product product = productMapper.selectById(item.getProductId());
        if (product != null) {
            Product prodUpdate = new Product();
            prodUpdate.setId(product.getId());
            prodUpdate.setSales(product.getSales() + item.getQuantity());
            productMapper.updateById(prodUpdate);
        }
    }
}

## 8. 安全与权限设计

### 8.1 数据归属校验

所有用户端接口必须校验数据归属：
- 购物车操作：`cart.userId == BaseContext.getCurrentId()`
- 订单操作：`order.userId == BaseContext.getCurrentId()`
- 地址操作：`address.userId == BaseContext.getCurrentId()`

### 8.2 订单状态机校验

```
待付款(0) ──支付──→ 待发货(1) ──发货──→ 待收货(2) ──确认收货──→ 已完成(3)
    │                   │                   │
    └──取消──→ 已取消(4)              └──售后──→ 售后中(5)
```

任何状态变更前必须校验当前状态合法性，防止状态跳变。

### 8.3 库存安全

- 订单创建时校验库存，但不立即扣减（支付成功后扣减）
- 模拟支付场景下，订单创建时即视为"锁定库存"
- 取消订单时恢复库存

### 8.4 快照机制

订单创建时将所有商品信息、地址信息快照存储，确保：
- 商品改名/改价不影响历史订单
- 地址变更不影响历史订单

-- ============================================================

### 12.2 关键实现要点

1. **订单号生成**：`AGS` + 16位时间戳 + 6位随机数，保证全局唯一
2. **快照机制**：订单创建时复制商品名称、图片、价格、规格，防止商品变更后影响历史订单
3. **库存校验**：订单创建前校验库存充足，但不立即扣减（支付后扣减，后续迭代）
4. **购物车清空**：订单创建成功后清空已结算的购物车条目
5. **状态机**：订单状态变更必须按序进行，非法状态跳变返回 OPERATION_ERROR
6. **事务保证**：订单创建、支付、发货等操作必须加 `@Transactional`，确保数据一致性
7. **数量累加**：购物车添加相同商品+规格时累加数量，不新增记录

### 12.3 开发顺序建议

```
建表 SQL → Entity → Mapper → DTO/VO → CartService → OrderService → PaymentService
          → CartController → OrderController → PaymentController → AdminOrderController
          → 联调测试
```

建议先完成购物车模块，再开发订单模块，最后开发支付和管理端订单接口。

### 12.4 注意事项

1. **订单表名**：`order` 是 SQL 保留字，建表时需用反引号 `` `order` `` 包裹
2. **软删除**：订单表建议不加 `@TableLogic`，订单数据不应被逻辑删除（需保留历史记录）
3. **库存扣减**：本期模拟支付不扣减库存，后续可加入 Redis 预扣库存 + 数据库乐观锁
4. **超时取消**：本期不实现订单超时自动取消，后续可用 Spring Schedule 定时任务扫描
5. **订单快照**：订单明细中的 `product_name`、`product_image`、`price` 均为创建时的快照值
