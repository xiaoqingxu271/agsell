## 1. 模块概述

### 1.1 模块定位

产地溯源是 agsell 系统的**农产品特色模块**，针对农产品 "信任缺失" 的核心痛点，建立 "从农田到餐桌" 的完整信息链路：



* **溯源信息管理（管理端）**：为商品绑定生产批次，记录种植户、产地、种植 / 采摘日期、质检结果、认证信息

* **生产记录管理（管理端）**：按批次记录播种、施肥、浇水、采收等生产环节的时间线

* **二维码溯源**：每个批次生成独立二维码，扫码即可查看完整溯源档案

* **用户端溯源展示**：商品详情页提供溯源入口，按批次号 / 扫码查看溯源档案（含生产记录时间线）

### 1.2 与需求文档的对应关系

本模块对应《需求文档》以下内容（均为文档已设计、当前代码未实现的部分）：



| 需求文档章节        | 内容                                        |
| ------------- | ----------------------------------------- |
| §12.2 农产品溯源体系 | 批次管理、二维码溯源、种植档案、质检报告、生产者信息                |
| §6.1 管理 - 溯源  | `AdminTraceabilityController`：溯源信息管理、生产记录 |
| §7.2.14 溯源信息表 | `traceability_info` 表设计                   |
| §7.2.15 生产记录表 | `production_record` 表设计                   |
| §12.3 溯源二维码生成 | ZXing 生成二维码，批次绑定唯一 URL                    |

### 1.3 与其他模块的关系



```
┌─────────────────────────────────────────────────────────────┐

│                        产地溯源模块                           │

│                                                             │

│  ┌─────────────────────┐      ┌─────────────────────┐       │

│  │   溯源信息管理        │      │   生产记录管理        │       │

│  │  (Admin端)          │      │   (Admin端)         │       │

│  │                     │      │                     │       │

│  │  批次信息 CRUD       │      │  播种/施肥/浇水/采收  │       │

│  │  二维码生成          │      │  记录时间线           │       │

│  └─────────┬───────────┘      └─────────┬───────────┘       │

│            │                            │                   │

│            │  1:N（一个批次多记录）        │                   │

│            └──────────────┬─────────────┘                   │

│                           ▼                                 │
```

溯源模块依赖商品模块（溯源信息必须挂在已存在的商品上），被用户端商品详情页和扫码溯源页引用，不依赖订单、购物车等交易模块。

## 2. 目标与范围

### 2.1 本期开发目标



* [ ] `traceability_info`、`production_record` 建表脚本（`sql/traceability_module.sql`）

* [ ] 溯源信息管理（管理端）：分页查询、新增、编辑、删除

* [ ] 生产记录管理（管理端）：列表、新增、编辑、删除

* [ ] 溯源二维码生成（ZXing），二维码图片上传 OSS 并持久化 URL

* [ ] 用户端溯源查询接口（按批次号 / 按商品 ID 查最新批次）

* [ ] 商品详情接口返回溯源摘要（`hasTrace` / `traceBatchNo`）

* [ ] 拦截器白名单配置（用户端溯源接口无需登录）

* [ ] 管理端前端：溯源管理页面（列表 + 新增 / 编辑 + 二维码预览 + 生产记录）

* [ ] 小程序端：商品详情溯源入口 + 溯源档案展示页

### 2.2 不在本期范围



* 真实物流对接（溯源不等同于物流轨迹）

* 区块链存证（需求文档未要求，可作论文 "后续展望"）

* 溯源信息与订单 / 批次号绑定的全链路（每单商品绑定具体批次，涉及库存批次化管理，改动大，列为后续扩展）

* 种植户端自助录入（当前由管理员统一录入）

### 3.2 ER 关系



```
product (1) ────< (N) traceability\_info (1) ────< (N) production\_record

&#x20; │                        │

&#x20; │                        └── 每批次一条二维码 URL

&#x20; └── 商品详情页展示最新批次溯源摘要
```



* 一个商品可挂多个批次（如不同种植时间、不同产地），用户端展示**最新批次**

* 一个批次可有多条生产记录，按 `record_date` 升序展示为时间线

* 删除溯源信息时，同一事务内级联逻辑删除该批次的生产记录

### 4.2 生产记录归属设计

生产记录**不单独建 Controller**，作为溯源信息的子资源由 `TraceabilityService` 统一管理（接口挂在 `/api/admin/traceability/...` 下），原因：



1. 生产记录无独立生命周期，脱离批次没有意义

2. 减少 Controller/Service 数量，与现有模块 "一个业务域一个 Service" 的风格一致

3. 管理端前端可在一个页面内完成 "溯源信息 + 生产记录" 的维护

#### 5.1.5 生成溯源二维码



```
POST /api/admin/traceability/{id}/generate-qr

Authorization: Bearer {token}

Response 200:

{

&#x20; "code": 0,

&#x20; "message": "ok",

&#x20; "data": { "qrCodeUrl": "https://.../trace/qr/B202609110001.png" }

}
```

**业务逻辑：**



1. 溯源信息不存在抛 `NOT_FOUND_ERROR`

2. 二维码内容：`{trace.base-url}/trace?batchNo={batchNo}`（`trace.base-url` 新增配置，见 §6.2）

3. ZXing 生成 300×300 PNG → 上传 OSS 至 `trace/qr/{batchNo}.png`（覆盖式，重复生成幂等）

4. 更新 `qr_code_url` 字段

5. 生成或上传失败抛 `OPERATION_ERROR`，不落库

**鉴权要求：** 必须登录（管理员）



***

```

&#x20; "message": "ok",

&#x20; "data": null

}
```

## 6. 核心业务逻辑

### 6.1 批次号生成规则



```
格式：B + yyyyMMdd + 4位当天序号

示例：B202609110001
```

**实现方式：**



1. 查询当天已生成的批次数 `n`，序号取 `n + 1`（`selectCount` 按 `batch_no LIKE 'B20260911%'`）

2. 拼接生成批次号，插入时依赖 `uk_batch_no` 唯一索引兜底

3. 若唯一索引冲突（并发同秒生成），捕获异常重试一次（序号 +1 后再查）

4. 仍失败则抛 `OPERATION_ERROR`

> 批次号生成后
>
> **不可修改**
>
> ，作为对外溯源标识被二维码、生产记录引用。

### 6.2 二维码生成与存储

**依赖新增（pom.xml）：**



```
\<!-- ZXing 二维码 -->

\<dependency>

&#x20;   \<groupId>com.google.zxing\</groupId>

&#x20;   \<artifactId>core\</artifactId>

&#x20;   \<version>3.5.3\</version>

\</dependency>

\<dependency>

&#x20;   \<groupId>com.google.zxing\</groupId>

&#x20;   \<artifactId>javase\</artifactId>

&#x20;   \<version>3.5.3\</version>

\</dependency>
```

**新增配置（application.yaml）：**



```
\# 溯源配置

trace:

&#x20; base-url: \${trace.base-url:http://localhost:8080/api}  # 溯源 H5 页面域名（扫码后访问）
```

**生成流程：**



```
batchNo ──> 二维码内容 = {trace.base-url}/trace?batchNo={batchNo}

&#x20;     │

&#x20;     ├─> ZXing QRCodeWriter.encode(content, QR\_CODE, 300, 300)

&#x20;     │         └─> BufferedImage（PNG 编码到 ByteArrayOutputStream）

&#x20;     │

&#x20;     ├─> FileUploadService 新增 uploadBytes(byte\[], objectKey, contentType)

&#x20;     │         └─> 上传 OSS，objectKey = trace/qr/{batchNo}.png（覆盖式，幂等）

&#x20;     │

&#x20;     └─> 返回可访问 URL ──> 更新 traceability\_info.qr\_code\_url
```

**设计要点：**



* 二维码内容为 URL 而非纯文本批次号：微信 "扫普通链接二维码打开小程序" 依赖 URL 形式，且 H5 场景可直接访问

* 图片持久化到 OSS 而非存 Base64：URL 可直接用于管理端预览和小程序 `<image>` 展示，数据库只存 URL

* `FileUploadService` 需新增一个 `uploadBytes` 方法（当前仅支持 `MultipartFile`），在 `OssClientProvider` 基础上封装，不改动现有上传接口

### 6.3 新鲜度计算（本期实现）

根据 `harvest_date` 距今天数计算新鲜度标签：



| 距采摘天数     | 等级     | 文案     |
| --------- | ------ | ------ |
| ≤ 3 天     | FRESH  | 现摘现发   |
| 4 \~ 7 天  | NORMAL | 新鲜     |
| 8 \~ 15 天 | FAIR   | 较新鲜    |
| > 15 天    | STALE  | 建议尽快食用 |



* `harvest_date` 为空时不返回 `freshness`

* 计算逻辑独立为一个方法（`FreshnessCalculator` 或 `TraceabilityServiceImpl` 私有方法），便于单元测试

### 6.4 事务边界



| 场景                | 事务范围                                         |
| ----------------- | -------------------------------------------- |
| 新增溯源信息 + 生产记录     | 一个 `@Transactional`                          |
| 删除溯源信息 + 级联删除生产记录 | 一个 `@Transactional`                          |
| 生成二维码             | 上传 OSS 成功后更新 `qr_code_url`，更新失败不影响图片（下次重试覆盖） |
| 新增 / 编辑生产记录       | 单条操作，无跨表事务                                   |
