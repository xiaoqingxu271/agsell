## 1. 模块概述

### 1.1 模块定位

商品管理与分类管理是 agsell 系统的核心业务模块，承担以下职责：

- **商品分类管理**：支持二级分类树形结构，增删改查、排序、状态管理，提供分类树和扁平列表两种接口
- **商品管理（管理端）**：商品列表分页查询、增删改查、状态切换（上架/下架）、分类筛选
- **商品浏览（用户端）**：商品列表分页查询、关键词搜索、多条件排序、商品详情、热销/新品推荐
- **规格管理**：多规格商品（如 500g/1kg 装）的增删改，规格独立价格与库存

### 1.2 与其他模块的关系

### 3.2 SQL 建表脚本

建表脚本存放于 `sql/product_module.sql`：

```sql
-- ============================================================
-- 商品分类表
-- ============================================================
CREATE TABLE IF NOT EXISTS `product_category` (
    `id`          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
    `name`        VARCHAR(50)  NOT NULL COMMENT '分类名称',
    `icon`        VARCHAR(255) DEFAULT NULL COMMENT '分类图标URL',
    `parent_id`   BIGINT       NOT NULL DEFAULT 0 COMMENT '父分类ID，0表示一级分类',
    `sort`        INT          NOT NULL DEFAULT 0 COMMENT '排序值，越大越靠前',
    `status`      TINYINT      NOT NULL DEFAULT 1 COMMENT '状态 0=禁用 1=启用',
    `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time` DATETIME     DEFAULT NULL ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    `deleted`     TINYINT      NOT NULL DEFAULT 0 COMMENT '软删除标记',
    PRIMARY KEY (`id`),
    KEY `idx_parent_id` (`parent_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='商品分类表';

-- ============================================================
-- 商品表
-- ============================================================
CREATE TABLE IF NOT EXISTS `product` (
    `id`             BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
    `name`           VARCHAR(100) NOT NULL COMMENT '商品名称',
    `subtitle`       VARCHAR(200) DEFAULT NULL COMMENT '副标题',
    `category_id`    BIGINT       NOT NULL COMMENT '分类ID',
    `price`          DECIMAL(10,2) NOT NULL COMMENT '售价',
    `original_price` DECIMAL(10,2) DEFAULT NULL COMMENT '原价',
    `stock`          INT          NOT NULL DEFAULT 0 COMMENT '库存',
    `sales`          INT          NOT NULL DEFAULT 0 COMMENT '销量',
    `main_image`     VARCHAR(255) DEFAULT NULL COMMENT '主图URL',
    `images`         TEXT COMMENT '图片数组JSON',
    `description`    LONGTEXT COMMENT '商品详情HTML',
    `origin`         VARCHAR(100) DEFAULT NULL COMMENT '产地',
    `harvest_date`   DATE DEFAULT NULL COMMENT '采摘/上市日期',
    `shelf_life`     VARCHAR(50) DEFAULT NULL COMMENT '保质期',
    `storage`        VARCHAR(50) DEFAULT NULL COMMENT '储存方式',
    `status`         TINYINT      NOT NULL DEFAULT 0 COMMENT '状态 0=下架 1=上架',
    `sort`           INT          NOT NULL DEFAULT 0 COMMENT '排序值',
    `create_time`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time`    DATETIME     DEFAULT NULL ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    `deleted`        TINYINT      NOT NULL DEFAULT 0 COMMENT '软删除标记',
    PRIMARY KEY (`id`),
    KEY `idx_category_id` (`category_id`),
    KEY `idx_status` (`status`),
    KEY `idx_name` (`name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='商品表';

-- ============================================================
-- 商品规格表
-- ============================================================
CREATE TABLE IF NOT EXISTS `product_spec` (
    `id`          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
    `product_id`  BIGINT       NOT NULL COMMENT '商品ID',
    `spec_name`   VARCHAR(50)  NOT NULL COMMENT '规格名称（如500g装）',
    `price`       DECIMAL(10,2) NOT NULL COMMENT '该规格价格',
    `stock`       INT          NOT NULL DEFAULT 0 COMMENT '该规格库存',
    `image`       VARCHAR(255) DEFAULT NULL COMMENT '规格图片URL',
    `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time` DATETIME     DEFAULT NULL ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    `deleted`     TINYINT      NOT NULL DEFAULT 0 COMMENT '软删除标记',
    PRIMARY KEY (`id`),
    KEY `idx_product_id` (`product_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='商品规格表';
```

### 4.2 分类管理 vs 商品管理的对比

| 维度 | 分类管理 | 商品管理 |
|------|----------|----------|
| 端 | 仅管理端 | 管理端 + 用户端 |
| 权限 | 管理员 | 管理员（管理端）/ 用户（用户端） |
| 数据结构 | 树形（parent_id 关联） | 扁平（分类关联） |

| 查询复杂度 | 简单（树形构建） | 中等（分页+筛选+关键词） |

## 5. 接口详细设计

### 5.1 分类管理接口（管理端 `/api/admin/category`）

#### 5.1.1 获取分类树

```http
GET /api/admin/category/tree
Authorization: Bearer {token}

Response 200:
{
  "code": 0,
  "message": "ok",
  "data": [
    {
      "id": 1,
      "name": "水果",
      "icon": null,
      "parentId": 0,
      "sort": 100,
      "createTime": "2026-08-25T10:00:00",
      "children": [
        {
          "id": 7,
          "name": "柑橘类",
          "icon": null,
          "parentId": 1,
          "sort": 10,
          "createTime": "2026-08-25T10:00:00",
          "children": []
        }
      ]
    }
  ]
}
```

**业务逻辑：**
1. 查询所有 `status=1` 的分类，按 `sort DESC` 排序
2. 构建 `LinkedHashMap<Long, CategoryTreeVO>` 保持插入顺序
3. 二次遍历将子节点挂载到对应父节点
4. 根节点（parentId=0 或父节点不存在）放入结果列表

**鉴权要求：** 必须登录（管理员）

#### 5.1.3 新增/更新分类

```http
POST /api/admin/category
Content-Type: application/json
Authorization: Bearer {token}

// 新增分类
Request Body:
{
  "name": "特产农产品",
  "icon": "https://...",
  "parentId": 0,
  "sort": 60
}

// 更新分类
Request Body:
{
  "id": 1,
  "name": "水果(新)",
  "icon": "https://...",
  "parentId": 0,
  "sort": 100
}

Response 200: { "code": 0, "message": "ok", "data": null }
```

**业务逻辑：**
1. 校验分类名称非空、长度 ≤ 20
2. 更新时检查不能将自身设为父分类
3. 更新时检查不能将子分类设为父分类（循环引用检测）
4. 新增时 status 默认 1

**校验失败返回：**
- 分类名称为空 → `PARAMS_ERROR`
- 分类名称超长 → `PARAMS_ERROR`
- 自身作为父分类 → `PARAMS_ERROR`
- 循环引用 → `PARAMS_ERROR`

**鉴权要求：** 必须登录（管理员）

---

#### 5.1.4 删除分类

```http
DELETE /api/admin/category/{id}
Authorization: Bearer {token}

Response 200: { "code": 0, "message": "ok", "data": null }
```

**业务逻辑：**
1. 查询分类是否存在
2. 检查是否有子分类（`parent_id = id`）
3. 检查是否有商品关联（`category_id = id`）
4. 通过 MyBatis-Plus `@TableLogic` 逻辑删除

**校验失败返回：**
- 分类不存在 → `NOT_FOUND_ERROR`
- 存在子分类 → `OPERATION_ERROR`（"该分类下存在子分类，无法删除"）
- 存在关联商品 → `OPERATION_ERROR`（"该分类下有商品关联，无法删除"）

**鉴权要求：** 必须登录（管理员）

---

#### 5.1.5 更新分类状态

```http
PUT /api/admin/category/{id}/status?status=0
Authorization: Bearer {token}

Response 200: { "code": 0, "message": "ok", "data": null }
```

**业务逻辑：** 更新 `status` 字段（0=禁用，1=启用）。禁用后分类树不再显示。

**校验失败返回：**
- 分类不存在 → `NOT_FOUND_ERROR`
- status 不为 0 或 1 → `PARAMS_ERROR`

**鉴权要求：** 必须登录（管理员）

## 6. 核心业务逻辑

### 6.1 分类树构建

```java
// ProductCategoryServiceImpl.getCategoryTree()
public List<CategoryTreeVO> getCategoryTree() {
    // 1. 查询所有启用分类，按 sort DESC 排序
    List<ProductCategory> allCategories = lambdaQuery()
            .eq(ProductCategory::getStatus, 1)
            .orderByDesc(ProductCategory::getSort)
            .list();

    // 2. 构建节点 Map（LinkedHashMap 保持插入顺序）
    Map<Long, CategoryTreeVO> nodeMap = new LinkedHashMap<>();
    for (ProductCategory cat : allCategories) {
        nodeMap.put(cat.getId(), convertToVO(cat));
    }

    // 3. 二次遍历，将子节点挂载到父节点
    List<CategoryTreeVO> rootNodes = new ArrayList<>();
    for (ProductCategory cat : allCategories) {
        CategoryTreeVO node = nodeMap.get(cat.getId());
        if (cat.getParentId() == null || cat.getParentId() == 0) {
            rootNodes.add(node); // 一级分类
        } else {
            CategoryTreeVO parent = nodeMap.get(cat.getParentId());
            if (parent != null) {
                parent.getChildren().add(node); // 挂载子节点
            } else {
                rootNodes.add(node); // 父节点不存在，作为独立根节点
            }
        }
    }
    return rootNodes;
}
```

**关键点：**
- 使用 `LinkedHashMap` 保持排序顺序
- 父节点不存在时，子节点降级为根节点（防止数据异常）
- 每节点初始化 `children = new ArrayList<>()`，空列表而非 null

### 6.2 循环引用检测

```java
// 检测 id 是否为 parentId 的后代节点
private boolean isDescendant(Long id, Long parentId) {
    if (parentId == null || parentId == 0) return false;
    ProductCategory parent = getById(parentId);
    if (parent == null) return false;
    if (parent.getId().equals(id)) return true;   // 找到循环
    if (parent.getParentId() == null || parent.getParentId() == 0) return false;
    return isDescendant(id, parent.getParentId()); // 递归向上查找
}
```

**场景：** 将分类 B 的父节点设为其子分类 C，会导致循环引用。此方法递归向上遍历父链，检测是否存在循环。

### 6.3 规格管理策略

采用"删除重建"策略（而非增量更新）：

```java
private void saveOrUpdateSpecs(Long productId, List<ProductSpecDTO> specs) {
    // 1. 删除该商品所有旧规格
    productSpecMapper.delete(
        new LambdaQueryWrapper<ProductSpec>()
            .eq(ProductSpec::getProductId, productId)
    );

    // 2. 批量插入新规格
    if (specs != null && !specs.isEmpty()) {
        List<ProductSpec> specList = specs.stream()
            .map(dto -> {
                ProductSpec spec = new ProductSpec();
                spec.setProductId(productId);
                spec.setSpecName(dto.getSpecName());
                spec.setPrice(dto.getPrice());
                spec.setStock(dto.getStock());
                spec.setImage(dto.getImage());
                return spec;
            }).collect(Collectors.toList());
        productSpecMapper.insert(specList);
    }
}
```

**优点：** 实现简单，避免部分更新的不一致问题。规格数量通常较少（2-5 个），性能影响可忽略。

### 11.2 关键实现要点

1. **分页转换**：MyBatis-Plus `Page<Entity>` 不能直接 `.convert()` 转 VO，需手动构造 `new Page<>()` 并设置 records
2. **JSON 解析**：商品图片字段 `images` 存储为 JSON 字符串，使用 Hutool `JSONUtil.toList()` 解析
3. **null 安全**：`switch(request.getSortBy())` 不能直接处理 null，需先做空判断
4. **规格全量更新**：采用删除重建策略，避免增量更新的不一致问题
5. **树形构建**：使用 LinkedHashMap 保持排序，二次遍历挂载子节点
6. **循环引用检测**：递归向上遍历父链，防止分类树形成环

### 11.3 开发顺序建议

```
建表 SQL → Entity → Mapper → DTO/VO → Service → Controller → 拦截器白名单 → 联调测试
```

### 11.4 注意事项

1. **软删除**：所有实体类均使用 `@TableLogic` 注解，删除操作自动设置 `deleted=1`
2. **自动填充**：`createTime` 和 `updateTime` 使用 MyBatis-Plus 自动填充
3. **分类树展示**：管理端使用树形组件（如 el-tree），用户端可使用扁平列表或级联选择器
4. **商品详情性能**：详情接口涉及 3 次额外查询（一级分类、二级分类、规格），后续可考虑缓存优化
5. **规格快照**：订单中的商品信息应保存快照（商品名称、价格），防止商品变更后历史订单信息失真
