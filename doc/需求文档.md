## 1. 项目概述

### 1.1 项目背景

随着乡村振兴战略的深入推进和互联网经济的蓬勃发展，农产品上行（农产品从产地直供城市消费者）已成为重要的民生课题。传统农产品销售渠道存在**信息不对称、中间环节多、损耗率高、溯源困难**等痛点。本项目旨在设计并实现一套轻量级、易部署的农产品/特产销售系统，打通"产地—平台—消费者"的直连链路。

### 1.2 项目目标

- 构建一套完整的农产品电商交易系统（三端一体）
- 实现用户浏览、选购、下单、支付的完整购物闭环
- 实现管理员对商品、订单、用户、内容的全面运营管控
- 体现农产品特色（产地溯源、时令推荐、新鲜度标识）
- 满足本科/专科毕业设计的完整性和可答辩性要求

### 1.3 系统边界

**系统包含**：
- 后端 API 服务（Spring Boot 单体）
- 管理后台 Web 应用（Vue + Element Plus）
- 微信小程序用户端（原生开发）

**系统不包含**：
- 商家入驻系统（后台直接由管理员添加商品，暂不做多商家模式）
- 物流配送系统对接（模拟配送状态流转）
- 支付对接（模拟支付流程，支持微信支付接口预留）

### 1.4 核心业务流程

```
[用户端] 浏览商品 → 加入购物车 → 提交订单 → 模拟支付 → 查看订单状态
                          ↓
                    待发货 → 待收货 → 已完成 → 评价
                          ↓
                    退款/售后

[管理端] 商品管理 → 订单处理 → 发货 → 售后处理 → 数据分析
```

## 8. 非功能性需求

### 8.1 性能需求
- 首页加载时间 ≤ 2 秒（4G 网络环境下）
- API 接口平均响应时间 ≤ 500ms
- 支持同时 100+ 用户在线访问
- 商品图片压缩存储，单张 ≤ 200KB

### 8.2 安全需求
- 用户密码 BCrypt 加密存储
- JWT Token 有效期 7 天，过期需重新登录
- 管理后台接口统一鉴权（Spring Security Filter）
- SQL 注入防护（MyBatis 参数化查询）
- XSS 防护（输入内容转义）
- 接口限流（同一 IP 1分钟内最多 60 次请求）

### 8.3 可用性需求
- 系统可用性 ≥ 99%（演示环境）
- 关键操作有明确的错误提示
- 表单提交前后端双重校验
- 文件上传限制类型和大小（图片 ≤ 5MB，仅 jpg/png/webp）

### 8.4 兼容性需求
- 管理后台兼容 Chrome、Edge、Firefox 最新版
- 小程序兼容微信基础库 2.25.0+
- 响应式布局适配 1280px 以上分辨率

### 8.5 可维护性需求
- 代码注释率 ≥ 15%
- 接口文档完整（Swagger / Apifox）
- 前后端分离，独立部署
- 数据库变更使用 Flyway 迁移脚本管理

## 9. 接口设计规范

### 9.1 统一响应格式

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "timestamp": 1724467200000
}
```

**状态码定义**：

| code | 含义 |
|------|------|
| 200 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未认证（Token 无效/过期） |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |
| 10001 | 用户未登录 |
| 10002 | 商品库存不足 |
| 10003 | 订单状态异常 |

### 9.2 分页响应格式

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "list": [],
    "total": 100,
    "page": 1,
    "pageSize": 15,
    "pages": 7
  }
}
```

### 9.3 认证方式
- 用户端：Header 中携带 `Authorization: Bearer {token}`
- 管理端：Header 中携带 `Authorization: Bearer {token}`
- Token 在登录成功后返回，前端存入 localStorage（管理端）/ wx.setStorageSync（小程序）

### 9.4 文件上传
- 接口：`POST /api/upload`
- 返回格式：`{ "url": "https://..." }`
- 支持 jpg/png/webp/gif，单文件 ≤ 5MB

### 12.1 核心业务流程图

#### 购物流程
```
用户打开小程序
    ↓
浏览首页/分类/搜索 → 进入商品详情
    ↓
选择规格 → 加入购物车 / 立即购买
    ↓
确认购物车 → 选择/填写收货地址
    ↓
提交订单 → 模拟支付 → 支付成功
    ↓
管理员后台处理订单（审核→发货→填写物流）
    ↓
用户收到商品 → 确认收货
    ↓
评价商品 → 订单完成
```

#### 订单状态流转
```
[待付款] ──支付成功──→ [待发货] ──管理员发货──→ [待收货] ──确认收货──→ [已完成]
    │                       │                        │
    ↓                       ↓                        ↓
[已取消]              [售后中]               [售后中]
                              ↓
                        [售后完成/关闭]
```

### 12.2 农产品特色功能说明

本系统针对农产品/特产销售场景设计了以下特色功能：

1. **产地溯源信息**：每个商品可记录产地、采摘日期、运输方式，增强消费者信任
2. **新鲜度标识**：根据采摘日期自动计算并展示"新鲜度"标签
3. **时令推荐**：首页根据当季商品自动推荐时令产品
4. **保鲜说明**：商品详情展示储存方式、保质期、冷链配送说明
5. **坏果包赔**：售后流程支持"品质问题"退款，体现农产品特殊性

#### 农产品溯源体系（特色模块）

针对农产品"信任缺失"的核心痛点，系统设计了一套完整的溯源体系：

- **批次管理**：每批商品绑定唯一批次号，关联种植/采摘/质检全流程记录
- **二维码溯源**：每个批次生成独立二维码，消费者扫码即可查看完整溯源信息
- **种植档案**：记录播种、施肥、浇水、采收等生产过程及时间线
- **质检报告**：支持上传农药残留检测报告、有机认证等资质文件
- **生产者信息**：展示种植户姓名、联系电话、产地地址，建立"从农田到餐桌"的信任链

#### 时令产品管理

- **时令标签**：商品可设置上市开始/结束日期，系统自动判断当前是否应季
- **预售模式**：支持未上市时令产品开启预售，锁定库存提前收款
- **应季推荐**：首页自动展示当季商品，提升转化率

### 12.3 技术难点及解决方案

| 难点 | 解决方案 |
|------|----------|
| 并发库存扣减 | 使用 Redis 预减库存 + 数据库乐观锁（version 字段） |
| 订单超时自动取消 | 使用 Spring Schedule 定时任务扫描超时未支付订单，自动取消并回滚库存 |
| 图片上传与存储 | 本地 MinIO 存储 + Nginx 静态资源服务；或对接阿里云 OSS |
| JWT 无状态认证 | Spring Security Filter 拦截 + Token 续签机制（临近过期自动刷新） |
| 多规格商品选择 | 规格表独立设计，购物车和订单中保留规格快照，防止商品信息变更影响历史订单 |
| 富文本图片上传 | 富文本编辑器集成图片上传接口，返回 URL 插入 |
| 溯源二维码生成 | 使用 ZXing 库生成二维码，每个批次绑定独立 URL（如 `https://xxx.com/trace?batch=xxx`） |
| 秒杀并发控制 | Redis 预扣库存 + 数据库乐观锁 + 防重提交（用户粒度去重） |
