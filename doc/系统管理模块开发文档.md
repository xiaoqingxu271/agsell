## 1. 背景与目标

### 1.1 背景

需求文档 §5.9「系统管理」是当前唯一整块未实现的需求模块：

- **管理员管理（P0）**：管理员列表、新增、编辑、删除、重置密码——完全空白，`sys_admin` 表目前仅有 1 个内置 admin 账号，无法支撑多管理员协作与权限治理。
- **系统配置（P1）**：平台名称、客服电话、运费设置——完全空白，`sys_config` 表未建，订单运费逻辑写死（`freight` 默认 0），无平台信息落点。
- **操作日志（P2）**：管理员关键操作审计——`sys_log` 表未建，无法追溯"谁在何时做了什么"。

同时存在一个**权限模型隐患**：`JwtAuthInterceptor` 只校验了"是管理员 token"（`type=admin`），**未按 `role` 细分权限**。即 `OPERATOR` 与 `ADMIN` 当前权限完全等价，需求文档 §3.2 权限矩阵的约束形同虚设。

### 1.2 目标

- 引入**超级管理员（SUPER_ADMIN）**角色，形成"SUPER_ADMIN → ADMIN → OPERATOR"三级 RBAC 模型，解决"由谁管理管理员"的权限归属问题
- 完成管理员 CRUD（新增/编辑/重置密码/启停/删除），配套 4 条自我保护规则
- 落地系统配置表，运费/满额包邮配置接入订单结算，平台信息（名称/客服电话）可配置
- 落地操作日志审计（登录、管理员操作、商品上下架、发货等关键动作），支持分页查询
- **顺带修复现状缺陷**：拦截器按 role 细分接口权限，让 OPERATOR 角色真正生效

### 1.3 非目标（本期明确不做）

- 细粒度菜单/按钮级权限（RBAC 完整模型，见 §11 扩展路径）
- 多租户 / 商家入驻
- 操作日志的导出、趋势分析看板
- 管理员头像上传、双因素认证

## 2. 现状分析与问题

### 2.1 现有实现

| 项 | 现状 |
|---|---|
| 角色定义 | `UserRoleEnum`：ADMIN（后台管理员）/ OPERATOR（后台运营）/ USER（普通用户），**无超级管理员** |
| 管理员表 | `sys_admin`：id（自增）/ username（uk 唯一）/ password（BCrypt）/ real_name / role / status / login_ip / login_time / deleted（逻辑删除），仅 1 条内置 admin 数据 |
| 认证 | `AdminAuthServiceImpl#login`：BCrypt 校验 → 生成 JWT（携带 role）→ Redis 存 token → `AdminContext` 存 adminId/role/jti |
| 鉴权 | `JwtAuthInterceptor`：`/api/admin/**` 仅校验 `type=admin`，**未按 role 做任何细分** |
| 管理员管理接口 | **不存在**（无 AdminSystemController） |
| 系统配置 | **不存在**（无 sys_config 表，订单 `freight` 写死） |
| 操作日志 | **不存在**（无 sys_log 表） |
| 管理端菜单 | `LayoutView.vue` 平铺 11 个菜单项，无分组、无按角色显隐 |

### 2.2 问题清单

| 问题 | 现状表现 | 影响 |
|---|---|---|
| 无管理员管理 | sys_admin 仅 1 个账号，无法新增运营账号 | 需求 §5.9.1 P0 空白，多管理员协作缺失 |
| OPERATOR 形同虚设 | 拦截器不按 role 细分，运营与管理员权限完全一致 | 权限矩阵失效，越权风险 |
| 无系统配置 | 运费写死 0、平台名称/客服电话无落点 | 需求 §5.9.2 P1 空白，运营无法调整 |
| 无操作日志 | 无法追溯管理员关键操作 | 需求 §5.9.2 P2 空白，审计缺失 |
| 平级互删风险 | 若直接实现管理员管理，A 管理员可删 B | 无最高权限主体，权限模型不自洽 |

## 3. 角色权限设计（RBAC 三级模型）

### 3.1 角色定义

| 角色 | 标识 | 定位 | 权限范围 |
|---|---|---|---|
| 超级管理员 | `SUPER_ADMIN` | 系统最高权限（内置 admin 账号） | 管理员管理、系统配置、操作日志 + 全部业务权限 |
| 运营管理员 | `ADMIN` | 业务运营管理 | 商品/订单/用户/评价/轮播图/售后/秒杀/溯源/热词等全部业务模块，**无系统管理权限** |
| 运营专员 | `OPERATOR` | 一线运营（按需求 §3.2 权限矩阵） | 仅商品 + 订单管理 |

> `SUPER_ADMIN` 为**新增角色值**（`UserRoleEnum` 增加枚举），`sys_admin.role` 字段沿用 VARCHAR(20)，无需改表结构，仅将内置 admin 账号的 role 从 `ADMIN` 升级为 `SUPER_ADMIN`。

### 3.2 权限矩阵（管理端）

| 功能模块 | SUPER_ADMIN | ADMIN | OPERATOR |
|---|:---:|:---:|:---:|
| 商品管理 | ✅ | ✅ | ✅ |
| 订单管理 | ✅ | ✅ | ✅ |
| 用户管理 | ✅ | ✅ | ❌ |
| 分类管理 | ✅ | ✅ | ✅ |
| 评价/轮播图/售后/秒杀/溯源/热词 | ✅ | ✅ | ❌ |
| 数据统计 | ✅ | ✅ | ✅ |
| **管理员管理** | ✅ | ❌ | ❌ |
| **系统配置** | ✅ | ❌ | ❌ |
| **操作日志** | ✅ | ❌ | ❌ |

### 3.3 自我保护规则（防"平级互删"悖论）

| 编号 | 规则 | 实现要点 |
|---|---|---|
| R1 | **不可操作自己** | 删除/启停/编辑自己时拒绝（`AdminContext.getCurrentAdminId()` 与目标 id 比对） |
| R2 | **至少保留一个超级管理员** | 删除/禁用目标为 SUPER_ADMIN 前，统计 SUPER_ADMIN 数量 ≤ 1 则拒绝 |
| R3 | **权限单向** | 仅高角色可操作低角色：SUPER_ADMIN 可操作 ADMIN/OPERATOR；ADMIN 不能操作 SUPER_ADMIN；OPERATOR 无系统管理入口 |
| R4 | **角色不越权授予** | 新增/编辑管理员时，目标角色只能 ≤ 当前角色（SUPER_ADMIN 才能创建 ADMIN/OPERATOR） |

### 3.4 与现有代码衔接

- `UserRoleEnum`：新增 `SUPER_ADMIN("SUPER_ADMIN", "超级管理员")`
- `JwtAuthInterceptor`：token 中已携带 `role`（`AdminAuthServiceImpl#generateAdminToken`），拦截器新增"系统管理路径需 SUPER_ADMIN"判断
- `AdminContext`：已有 `getCurrentRole()`，服务层保护规则直接可用
- `ErrorCode`：复用 `ADMIN_NO_AUTH_ERROR(40201, "管理员无权限")`

## 5. 数据模型设计

### 5.1 sys_admin 表（无结构变更，仅数据升级）

```sql
-- 内置 admin 账号升级为超级管理员（幂等：仅当不存在 SUPER_ADMIN 时执行）
UPDATE sys_admin
SET role = 'SUPER_ADMIN'
WHERE username = 'admin'
  AND role <> 'SUPER_ADMIN'
  AND NOT EXISTS (SELECT 1 FROM sys_admin WHERE role = 'SUPER_ADMIN');
```

> 设计说明：`role` 字段为 VARCHAR(20)，直接承载 `SUPER_ADMIN`，无需 ALTER。已有 admin 账号升级后即拥有系统管理入口。

### 5.2 新增系统配置表 `sys_config`（需求 §7.2.13 落地）

```sql
CREATE TABLE IF NOT EXISTS `sys_config` (
    `id`          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
    `config_key`  VARCHAR(50)  NOT NULL COMMENT '配置键',
    `config_value` VARCHAR(500) DEFAULT NULL COMMENT '配置值',
    `description` VARCHAR(100) DEFAULT NULL COMMENT '配置描述',
    `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time` DATETIME     DEFAULT NULL ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_config_key` (`config_key`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='系统配置表';
```

**初始配置项（seed 数据）**：

| config_key | config_value | description |
|---|---|---|
| `platform_name` | 农产品销售系统 | 平台名称（小程序/后台标题展示） |
| `service_phone` | 400-000-0000 | 客服电话（个人中心"联系客服"展示） |
| `default_freight` | 0 | 默认运费（元），订单结算运费兜底值 |
| `free_shipping_threshold` | 0 | 满额包邮阈值（元），0 = 不启用包邮 |

### 5.3 新增操作日志表 `sys_log`（需求 §7.2.12 落地）

```sql
CREATE TABLE IF NOT EXISTS `sys_log` (
    `id`          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
    `admin_id`    BIGINT       NOT NULL COMMENT '操作人ID',
    `admin_name`  VARCHAR(50)  NOT NULL COMMENT '操作人姓名',
    `module`      VARCHAR(50)  NOT NULL COMMENT '操作模块',
    `action`      VARCHAR(50)  NOT NULL COMMENT '操作动作',
    `content`     VARCHAR(500) DEFAULT NULL COMMENT '操作内容描述',
    `ip`          VARCHAR(50)  DEFAULT NULL COMMENT '操作IP',
    `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '操作时间',
    PRIMARY KEY (`id`),
    KEY `idx_admin_id` (`admin_id`),
    KEY `idx_module` (`module`),
    KEY `idx_create_time` (`create_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='操作日志表';
```

> 设计说明：日志表为**只追加**（insert + select），不更新不删除（本期不做日志清理，毕设规模可接受）。索引覆盖 admin_id / module / create_time 三个查询维度。

### 5.4 落地脚本 `sql/system_module.sql`

内容为 §5.1 + §5.2 + §5.3 三段，全部幂等（IF NOT EXISTS / 条件 UPDATE），与现有 `search_module.sql` 等模块脚本同目录管理，可重复执行。

## 6. 后端接口设计

统一前缀 `/api/admin/system/**`，**仅 SUPER_ADMIN 可访问**（拦截器强制）。统一响应 `BaseResponse<T>`，错误码复用现有枚举。

## 7. 核心实现要点

### 7.1 新增依赖

**无需新增任何 Maven 依赖**。AOP 使用 Spring Boot 内置 `spring-boot-starter-aop`（当前工程已通过 starter-web 传递引入，确认 pom 中无则显式添加）；日志查询走 MyBatis-Plus 分页，配置读写走 BaseMapper，均为现有能力。

### 7.2 拦截器 role 细分（JwtAuthInterceptor 改造）

在现有逻辑中，`isAdminApi` 分支内新增系统管理路径判断：

```java
boolean isAdminApi = uri.startsWith("/api/admin/");
boolean isSystemApi = uri.startsWith("/api/admin/system/");
// ... 现有 token 校验逻辑不变 ...
if (isAdminApi || (isFileUploadApi && "admin".equals(type))) {
    if (!"admin".equals(type)) {
        throw new BusinessException(ErrorCode.NO_AUTH_ERROR, "无管理员权限");
    }
    String role = claims.get("role", String.class);
    // 新增：系统管理接口仅 SUPER_ADMIN
    if (isSystemApi && !"SUPER_ADMIN".equals(role)) {
        throw new BusinessException(ErrorCode.ADMIN_NO_AUTH_ERROR, "仅超级管理员可操作系统管理");
    }
    // ... 现有 Redis token 校验、AdminContext.setCurrentAdmin 不变 ...
}
```

> 取舍说明：采用**拦截器路径判断**而非注解（`@RequireRole`），与现有白名单风格一致、实现最简，毕设规模足够。后续要细粒度权限再迁移到注解方案（见 §11）。

### 7.3 管理员 CRUD 与保护规则（AdminSystemServiceImpl）

```java
@Override
@Transactional
public void deleteAdmin(Long id) {
    Long currentId = AdminContext.getCurrentAdminId();
    String currentRole = AdminContext.getCurrentRole();
    ThrowUtils.throwIf(id == null, ErrorCode.PARAMS_ERROR, "管理员ID不能为空");
    // R1：不可操作自己
    ThrowUtils.throwIf(id.equals(currentId), ErrorCode.OPERATION_ERROR, "不能删除当前登录账号");
    SysAdmin target = adminMapper.selectById(id);
    ThrowUtils.throwIf(target == null, ErrorCode.NOT_FOUND_ERROR, "管理员不存在");
    // R3：权限单向（当前角色必须高于目标角色）
    checkCanOperate(currentRole, target.getRole());
    // R2：至少保留一个超级管理员
    if ("SUPER_ADMIN".equals(target.getRole())) {
        Long superCount = adminMapper.selectCount(
                new LambdaQueryWrapper<SysAdmin>()
                        .eq(SysAdmin::getRole, "SUPER_ADMIN")
                        .eq(SysAdmin::getStatus, 1)
                        .eq(SysAdmin::getDeleted, 0));
        ThrowUtils.throwIf(superCount <= 1, ErrorCode.OPERATION_ERROR, "至少保留一个超级管理员");
    }
    adminMapper.deleteById(id); // MyBatis-Plus 逻辑删除
}

/** R3 判定：角色等级 ADMIN=1 < SUPER_ADMIN=2，OPERATOR=0 */
private void checkCanOperate(String currentRole, String targetRole) {
    int lv = roleLevel(currentRole);
    int tv = roleLevel(targetRole);
    ThrowUtils.throwIf(lv < tv, ErrorCode.ADMIN_NO_AUTH_ERROR, "无权操作更高权限的管理员");
    ThrowUtils.throwIf(lv == tv && !"SUPER_ADMIN".equals(currentRole),
            ErrorCode.ADMIN_NO_AUTH_ERROR, "同级管理员不可互相操作");
}

private int roleLevel(String role) {
    return switch (role == null ? "" : role) {
        case "SUPER_ADMIN" -> 2;
        case "ADMIN" -> 1;
        default -> 0;
    };
}
```

其他实现要点：

- **新增管理员**：username 唯一校验（`uk_username` + 前置 selectCount 友好提示）、密码长度 ≥ 6、BCrypt 加密（`cn.hutool.crypto.digest.BCrypt.hashpw`）、role 仅允许 `ADMIN`/`OPERATOR`（**不允许创建第二个 SUPER_ADMIN**，保证 R2 简单成立——超级管理员保持唯一）
- **重置密码**：newPassword ≥ 6 位，BCrypt 加密后 updateById
- **启停**：status 0/1 校验，复用 R1/R2/R3
- **编辑**：仅允许改 realName / role，role 变更遵循 R4（目标角色 ≤ 当前角色）

```java
/** 批量更新：仅接受白名单键，防注入任意配置 */
public void updateConfigs(List<ConfigItemVO> items) {
    for (ConfigItemVO item : items) {
        ThrowUtils.throwIf(!ALLOWED_KEYS.contains(item.getConfigKey()),
                ErrorCode.PARAMS_ERROR, "非法配置键: " + item.getConfigKey());
        SysConfig exist = configMapper.selectOne(
                new LambdaQueryWrapper<SysConfig>().eq(SysConfig::getConfigKey, item.getConfigKey()));
        if (exist == null) {
            SysConfig cfg = new SysConfig();
            cfg.setConfigKey(item.getConfigKey());
            cfg.setConfigValue(item.getConfigValue());
            configMapper.insert(cfg);
        } else {
            SysConfig update = new SysConfig();
            update.setId(exist.getId());
            update.setConfigValue(item.getConfigValue());
            configMapper.updateById(update);
        }
    }
}
```

### 7.5 操作日志 AOP（OperationLogAspect）

**注解** `@OperationLog(module = "管理员管理", action = "新增管理员")`：

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface OperationLog {
    String module();  // 模块名：管理员管理/系统配置/商品管理/订单管理...
    String action();  // 动作：新增/编辑/删除/发货/上下架...
}
```

**切面**（环绕通知，成功后才记录）：

```java
@Aspect
@Component
@RequiredArgsConstructor
public class OperationLogAspect {

    private final SysLogMapper sysLogMapper;
    // 简易线程池，避免日志写入拖慢主流程（失败仅 warn，不影响业务）
    private final ExecutorService executor = Executors.newFixedThreadPool(2);

    @Around("@annotation(operationLog)")
    public Object around(ProceedingJoinPoint pjp, OperationLog operationLog) throws Throwable {
        Object result = pjp.proceed(); // 业务执行
        try {
            Long adminId = AdminContext.getCurrentAdminId();
            if (adminId != null) {
                executor.submit(() -> writeLog(pjp, operationLog, adminId));
            }
        } catch (Exception e) {
            log.warn("操作日志写入失败", e);
        }
        return result;
    }

    private void writeLog(ProceedingJoinPoint pjp, OperationLog op, Long adminId) {
        SysLog log = new SysLog();
        log.setAdminId(adminId);
        // adminName 从 SysAdminMapper 按需查询或由调用方传入；简化：从 AdminContext 扩展
        log.setModule(op.module());
        log.setAction(op.action());
        log.setContent(buildContent(pjp)); // 截取关键参数（如新增账号 username）
        log.setIp(currentIp());             // RequestContextHolder 取 remoteAddr
        sysLogMapper.insert(log);
    }
}
```

**本期加注解的接口**（覆盖关键审计点）：

| 接口 | module / action |
|---|---|
| `POST /admin/login`（登录成功） | 认证 / 管理员登录 |
| 管理员 CRUD 全部 5 个写接口 | 管理员管理 / 新增·编辑·重置密码·启停·删除 |
| `PUT /admin/system/config` | 系统配置 / 更新配置 |
| `POST /admin/product/{id}/status`（上下架） | 商品管理 / 上架·下架 |
| `POST /admin/order/{id}/ship`（发货） | 订单管理 / 发货 |

> 取舍说明：本期日志覆盖"系统管理自身 + 登录 + 商品上下架 + 发货"等核心审计点，其他业务接口（如评价回复、轮播图编辑）可在验收后按需补注解，零成本增量。
