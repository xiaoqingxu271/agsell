## 1. 模块概述

### 1.1 模块定位

评价和轮播图模块分别承担系统的内容生产和展示职责：

- **评价模块**：交易闭环的最后一环，用户完成订单后可对商品进行评分和文字/图片评价，促进平台口碑建设
- **轮播图模块**：首页流量分发核心，管理员可配置促销活动、新品推荐等内容，提升转化率

### 1.2 与其他模块的关系

```
┌─────────────────────────────────────────────────────────────────┐
│                      评价与轮播图模块                            │
│                                                                 │
│  ┌──────────────────┐    ┌──────────────────┐                 │
│  │     评价模块      │    │    轮播图模块     │                 │
│  │  (用户+管理端)   │    │   (仅管理端)     │                 │
│  └────────┬─────────┘    └────────┬─────────┘                 │
│           │                       │                            │
│           │ 引用                   │ 独立 CRUD                  │
│           ▼                       ▼                            │
│  ┌─────────────────┐    ┌──────────────────┐                  │
│  │   订单模块       │    │   商品模块        │                  │
│  │  order          │    │  product         │                  │
│  └─────────────────┘    └──────────────────┘                  │
│           │                       │                            │
│           │ 只能评价已完成订单      │ 商品详情页展示评价          │

│  └──────────────────────────────────────────────┘             │
└─────────────────────────────────────────────────────────────┘
```

前置依赖：订单模块（评价入口）、商品模块（评价关联）、用户模块（鉴权）。

## 5. 接口详细设计

### 5.1 评价接口（`/api/review`）

#### 5.1.1 提交评价

```http
POST /api/review
Content-Type: application/json
Authorization: Bearer {token}

Request Body:
{
  "orderId": 1,
  "rating": 5,
  "content": "商品很好，新鲜好吃！",
  "images": ["https://...", "https://..."],
  "isAnonymous": 0
}

Response 200:
{
  "code": 0,
  "message": "ok",
  "data": null
}
```

**业务逻辑：**
1. 校验评价订单是否存在且属于当前用户
2. 校验订单状态为"已完成"（status=3）
3. 检查是否已评价（同一订单只能评价一次）
4. 校验评分范围 1-5
5. 校验评价内容长度 ≤ 500
6. 插入评价记录

**参数校验：**
- orderId 为空 → `PARAMS_ERROR`
- 订单不存在/非当前用户 → `NOT_FOUND_ERROR`
- 订单未完成 → `OPERATION_ERROR`
- 已评价过 → `OPERATION_ERROR`（"该订单已评价"）
- rating 不在 1-5 → `PARAMS_ERROR`
- content 超长 → `PARAMS_ERROR`

**鉴权要求：** 必须登录


```
    │
    ▼
┌──────────────────────┐

└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│ 2. 校验订单状态为"已完成"  │
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│ 3. 校验未评价过该订单    │
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│ 4. 校验评分 1-5       │
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│ 5. 校验内容长度 ≤ 500  │
└──────────┬───────────┘
           │
           ▼
        保存评价
```

### 6.2 评价与订单的关联

```java
// 校验订单
Order order = orderMapper.selectOne(new LambdaQueryWrapper<Order>()
        .eq(Order::getId, request.getOrderId())
        .eq(Order::getUserId, userId));
ThrowUtils.throwIf(order == null, ErrorCode.NOT_FOUND_ERROR, "订单不存在");

// 校验订单状态为已完成
ThrowUtils.throwIf(order.getStatus() != 3,
        ErrorCode.OPERATION_ERROR, "只有已完成的订单才能评价");

// 校验是否已评价
long existCount = lambdaQuery()
        .eq(Review::getOrderId, request.getOrderId())
        .count();
ThrowUtils.throwIf(existCount > 0,
        ErrorCode.OPERATION_ERROR, "该订单已评价");
```

### 6.3 商品评价列表（含用户信息关联）

```java
@Override
public Page<ReviewVO> listProductReviews(Long productId, int pageNum, int pageSize) {
    // 查询评价列表
    Page<Review> page = lambdaQuery()
            .eq(Review::getProductId, productId)
            .eq(Review::getDeleted, 0)
            .orderByDesc(Review::getCreateTime)
            .page(new Page<>(pageNum, pageSize));

    // 批量查询用户信息（避免 N+1）
    List<Long> userIds = page.getRecords().stream()
            .map(Review::getUserId)
            .distinct()
            .collect(Collectors.toList());
    List<SysUser> users = userMapper.selectBatchIds(userIds);
    Map<Long, SysUser> userMap = users.stream()
            .collect(Collectors.toMap(SysUser::getId, u -> u, (a, b) -> a));

    // 批量查询商品信息
    List<Long> productIds = page.getRecords().stream()
            .map(Review::getProductId)
            .distinct()
            .collect(Collectors.toList());
    Map<Long, Product> productMap = productMapper.selectBatchIds(productIds)
            .stream()
            .collect(Collectors.toMap(Product::getId, p -> p, (a, b) -> a));

    // 构建 VO
    Page<ReviewVO> result = new Page<>(page.getCurrent(), page.getSize(), page.getTotal());
    result.setRecords(page.getRecords().stream()
            .map(r -> convertToVO(r, userMap.get(r.getUserId()), productMap.get(r.getProductId())))
            .collect(Collectors.toList()));
    return result;
}
```

## 7. 安全与权限设计

### 7.1 评价安全

| 安全措施 | 说明 |
|----------|------|
| 订单归属校验 | 只能评价自己的订单 |
| 状态校验 | 只能评价已完成订单 |
| 唯一性校验 | 同一订单只能评价一次 |
| 内容长度限制 | 评价内容 ≤ 500 字 |
| 评分范围校验 | rating 1-5 |
| 匿名评价 | 支持匿名，隐藏用户名 |

### 7.2 轮播图安全

| 安全措施 | 说明 |
|----------|------|
| 仅管理员可操作 | 所有 CRUD 接口需管理员认证 |

### 11.1 SQL 建表脚本

```sql
-- ============================================================
-- 评价表
-- ============================================================
CREATE TABLE IF NOT EXISTS `review` (
    `id`            BIGINT         NOT NULL AUTO_INCREMENT COMMENT '主键',
    `order_id`      BIGINT         NOT NULL COMMENT '订单ID',
    `product_id`    BIGINT         NOT NULL COMMENT '商品ID',
    `user_id`       BIGINT         NOT NULL COMMENT '用户ID',
    `rating`        TINYINT        NOT NULL COMMENT '评分 1-5',
    `content`       VARCHAR(500)   DEFAULT NULL COMMENT '评价内容',
    `images`        TEXT COMMENT '评价图片JSON数组',
    `reply_content` VARCHAR(500)   DEFAULT NULL COMMENT '卖家回复',
    `reply_time`    DATETIME       DEFAULT NULL COMMENT '回复时间',
    `is_anonymous`  TINYINT        NOT NULL DEFAULT 0 COMMENT '是否匿名 0=否 1=是',
    `create_time`   DATETIME       NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time`   DATETIME       DEFAULT NULL ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    `deleted`       TINYINT        NOT NULL DEFAULT 0 COMMENT '软删除标记',
    PRIMARY KEY (`id`),
    KEY `idx_order_id` (`order_id`),
    KEY `idx_product_id` (`product_id`),
    KEY `idx_user_id` (`user_id`),
    UNIQUE KEY `uk_order_id` (`order_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='评价表';

-- ============================================================
-- 轮播图表
-- ============================================================
CREATE TABLE IF NOT EXISTS `banner` (
    `id`          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
    `title`       VARCHAR(100) DEFAULT NULL COMMENT '标题',
    `image`       VARCHAR(255) NOT NULL COMMENT '图片URL',
    `link`        VARCHAR(255) DEFAULT NULL COMMENT '跳转链接',
    `sort`        INT          NOT NULL DEFAULT 0 COMMENT '排序值，越大越靠前',
    `status`      TINYINT      NOT NULL DEFAULT 1 COMMENT '状态 0=禁用 1=启用',
    `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time` DATETIME     DEFAULT NULL ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    `deleted`     TINYINT      NOT NULL DEFAULT 0 COMMENT '软删除标记',
    PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='轮播图表';
```

### 11.2 关键实现要点

1. **评价唯一性**：`order_id` 设置唯一索引 `uk_order_id`，防止重复评价
2. **N+1 查询优化**：评价列表批量查询用户信息和商品信息，避免循环内查库
3. **匿名评价**：展示时根据 `is_anonymous` 字段决定是否隐藏用户名
4. **软删除**：评价和轮播图均使用 `@TableLogic`，删除后数据可恢复
5. **订单状态校验**：只能评价 status=3（已完成）的订单
6. **轮播图排序**：新增时取最大 sort + 10，支持手动调整

### 11.3 开发顺序建议

```
建表 SQL → Entity → Mapper → DTO/VO → BannerService → ReviewService
          → BannerController → ReviewController → AdminController
          → 拦截器白名单 → 联调测试
```

建议先完成轮播图（简单 CRUD），再开发评价（涉及多表关联和状态校验）。

### 11.4 注意事项

1. **评价与订单关联**：评价必须关联已完成订单，前端需在订单详情页展示"评价"按钮
2. **图片字段**：本期使用 URL 字符串，图片上传功能后续对接 MinIO/OSS
3. **匿名评价**：is_anonymous=1 时，管理端仍可见用户信息（用于审核），仅用户端隐藏
4. **轮播图 link**：可为空（不跳转），也可为商品详情页、分类页或外部 URL
5. **评价回复**：卖家回复后可再次编辑，不限制次数
