# 手动测试清单：RAG 与大模型智能体能力核对

> 适用范围：毕设《基于RAG与大模型智能体的农产品电商智能导购系统的设计与实现》答辩前的逐项人工验收。
> 每条给出**可直接复制的测试输入**与**判定标准（预期结果）**，逐条勾选并在文末表格记录实际结果。
> 清单依据 `ai-service/app/` 实际代码与 `config.py` 阈值编写，预期结果与实现逻辑一一对应。

## 使用说明

**推荐测试入口**（按优先级）：
1. **H5/小程序聊天页**：`我的 → AI 智能客服`；商详页点 `客服`（会带商品上下文，测 C 组必用）
2. **管理后台**：`AI 知识库`、`AI 转人工工单`、`评价管理`、仪表盘口碑饼图
3. **HTTP 直连**（备用，测降级时用）：
   - Java 网关：`POST http://127.0.0.1:8080/api/ai/chat`、`POST /api/ai/chat/stream`（游客可用，可选带 JWT）
   - Python 直连：`POST http://127.0.0.1:8000/v1/chat`，需带请求头 `X-Internal-Key: <ai-service/.env 里的 JAVA_INTERNAL_KEY>`（或本地临时设 `ALLOW_ANON_CHAT=1` 放行）

**观察"智能体到底调了哪个工具"的四个渠道**：
| 渠道 | 看什么 |
|---|---|
| 聊天气泡下方"依据"标签 | kb_search 命中的 FAQ 条目（id+问句），引用证据链 |
| 气泡下方商品卡片 | product_search 的返回（≤4 张卡） |
| ai-service 控制台日志（`docker compose logs -f ai-service`） | 每次工具调用、转人工原因、降级 WARNING |
| 管理后台 `AI 知识库 → 运营卡` | 近 7 日工具分布条形图、拒答率、对话量 |

**记录模板**：每测完一组，在文末「测试记录表」填：编号 / 实际现象 / 通过？/ 备注（截图编号）。

## 第 1 部分：RAG 检索正确性（知识库命中）

> 入口：AI 聊天页，游客即可。判定点：①答案内容与知识库一致 ②气泡下方出现"依据"引用标签 ③引用条目的问句与所问对得上。

种子知识库共 9 类 36 条平台规则（platform/account/product/order/shipping/aftersales/review/trace/seckill）+ 商品域条目 + 溯源条目。以下按类各挑代表问法：

- [ ] **A1 运费**：`运费怎么计算？` → 答案口径与系统设置一致（当前为 **2 元/笔**，2026-10 与 sys_config 对齐过），带依据标签
- [ ] **A2 发货时限**：`下单后多久发货？` → 答出承诺时限
- [ ] **A3 退换货政策**：`你们支持几天无理由退换？` / `退货的运费由谁承担？` → 答对政策口径（政策咨询归 FAQ 通道，不是查自己的售后单）
- [ ] **A4 支付方式**：`支付方式里有花呗吗？` / `支持哪些支付方式？` → 与实际配置一致
- [ ] **A5 优惠券×秒杀交叉**：`优惠券可以和秒杀价同时用吗？` → 答对玩法规则
- [ ] **A6 溯源操作**：`溯源二维码怎么使用？` / `哪些商品支持溯源？` → 答对操作路径
- [ ] **A7 售后条件**：`签收之后发现坏了还能申请退款吗？` / `申请售后需要满足什么条件？` → 答对
- [ ] **A8 账号类**：`登录状态会失效吗？` → 答对
- [ ] **A9 **语义改写**（不抄原话，考语义通道）**：`寄到新疆额外收钱吗`（原话是"运费怎么计算"）、`收货后几天内可以退`（原话含"无理由"）→ 仍能命中正确条目；这正是向量通道存在意义
- [ ] **A10 商品域问答**：`「<P0.5 挑的商品名>」这个商品有什么特点？` → 答案含产地/储存方式/保质期/价格（product_knowledge 条目内容）
- [ ] **A11 类目问答**：`「<类目名>」类目都有哪些商品？` → 报出该类目在售款数与价格带
- [ ] **A12 溯源深问**：挑一个有生产记录的商品问 `这个<商品名>是什么时候采收/生产的？用过什么肥？` → 能依据 trace_knowledge 切块条目回答（此问同时验证长文档切分入库效果）
- [ ] **A13 引用一致性抽查**：任选上面 3 条的回答，与管理后台 FAQ 列表原文逐句比对 → 没有编造原文没有的内容
- [ ] **A14 多条目聚合**：问一个可能跨条目的问题，如 `第一次买，从下单到收货流程是怎样的？` → 回答能组织多个条目信息且每段有依据，不混淆

## 第 2 部分：RAG 反幻觉闸门（拒答与防泄漏）

> 这是论文核心卖点，逐条必测。判定点：**确定性拒答话术**（不是 LLM 编的答案）、不出现商品卡片、答非所问内容为零。

- [ ] **B1 纯域外常识**：`现在油价多少？` → 拒答，不答食用油价格（这是历史泄漏样本，2026-10-24 复测已由"确认带加验"修复）
- [ ] **B2 域外生活问答**：`明天天气怎么样？` `帮我写一首关于秋天的诗` → 拒答或明确说明是购物助手，不写诗
- [ ] **B3 域外导购（带"推荐"停用词陷阱）**：`推荐一部好看的美剧` → 拒答。历史坑：通用词"推荐"曾把问题带进知识库，已加停用词过滤
- [ ] **B4 域外商品请求**（对话导购闸门 REC_MIN_SCORE=0.47 的泄漏探针，逐条测）：
  - `我想买个相机拍风景` → 无卡片
  - `给我推荐一支口红吧` → 无卡片
  - `有什么好用的洗地机` → 无卡片
  - `附近哪家健身房年卡便宜` → 无卡片
  （全部 8 条探针见 `ai-service/scripts/eval_data/agent_probe_ood.json`；判定口径：**泄漏 = 拿到商品卡片**，拒答或根本不调工具都算通过）
- [ ] **B5 词面相近的域外**：`手机壳哪个牌子好` → 不应把"带壳毛豆"之类农产品端出来（0.47 阈值就是为这句定的）
- [ ] **B6 域内但库未覆盖**：问一个平台相关但知识库没写的问题，如 `你们公司在哪个城市注册的？` → 检索为空走确定性拒答，不编造公司地址
- [ ] **B7 拒答后的引导**：B1~B6 拒答话术是否引导用户"换个说法/回平台咨询/拨客服电话"，而不是生硬结束
- [ ] **B8 边界确认**：`帮我比较一下 iPhone 和华为手机` → 域外拒答；紧接 `那苹果和脐橙哪个好` → 正常走导购（拒答不能"殃及"域内）

## 第 3 部分：智能体工具编排（6 个工具逐一核对）

> 工具目录在 `ai-service/app/agent/tool_defs.py`：kb_search / product_search / order_query / logistics_query / after_sales_query / escalate_human。选择权在 LLM 的 function calling，把关在执行器。

- [ ] **C1 kb_search 路由**：问 A1 中任一政策问题后，看运营卡"工具分布"出现 kb_search 计数
- [ ] **C2 product_search·品类点名**：`推荐点水果` → 返回卡片 ≤4 张（REC_CARD_LIMIT=4），名字含品类词的（如水果玉米）置顶（LIKE 命中重排后仍置顶）
- [ ] **C3 product_search·描述性需求**（无品类词，考语义召回 + 查询改写）：`50 元以内适合送礼的柑橘` → 卡片是柑橘类、价格 ≤50；模型应把 query 补全成完整句
- [ ] **C4 product_search·价格约束**：`100 块以内的大米` → 卡片全部 ≤100 元
- [ ] **C5 域外导购拒答**：`帮我挑个跑步鞋` → 确定性拒答，不走热销兜底、不经 LLM（inDomain=false 出口）
- [ ] **C6 商详指代 product_qa**（重点，测结构判据）：从**商详页**点客服进入，问 `这个能放多久？怎么保存？` → 回答围绕**当前商品**的事实（保质期/储存方式），气泡卡是这件商品本身，不端别的商品。历史实测：这类指代句向量分与真品类问句重叠，靠"有 productId 且无 keyword"结构判据分流
- [ ] **C7 商详页问别的**：商详页上下文里问 `你们运费怎么算` → 正确切到 kb_search 而不是硬答商品（hint 机制让模型下次带 keyword）
- [ ] **C8 order_query·已登录**：登录后问 `我最近买了什么？` → 报出真实订单（最近 5 条内）；再问 `订单 AGS2026... 的详情`（真实单号）→ 报出该单明细
- [ ] **C9 order_query·游客闸门**：退出登录问 `查一下我的订单` → 引导登录话术（need_login 出口），**不报错、不泄露他人数据**
- [ ] **C10 logistics_query**：`我的快递到哪了？` → 返回最近一笔订单的物流轨迹；不指定单号时自动取最近订单
- [ ] **C11 after_sales_query**：`我的退款处理得怎么样了？` → 报出售后单进度。注意区分：问"退款进度"走售后查询，问"退货政策"走 FAQ —— 两句各测一次
- [ ] **C12 escalate_human**：`我要投诉你们！东西是坏的必须给我说法！` → 转人工话术 + **管理后台"AI 转人工工单"页出现新工单**（含 reason）；工单点"处理"填备注 → 状态变已处理（闭环）
- [ ] **C13 多意图并行**（智能体核心卖点）：一句话塞两个诉求：`我的订单到哪了？顺便说下运费怎么算` → 一轮内并行发出多个 tool_calls，回答同时包含物流信息与运费政策（看日志确认并行调用而非只答其一）
- [ ] **C14 三诉求叠加**：`查下我的订单，再推荐点水果，顺便问下怎么申请售后` → 三类信息都在（AGENT_MAX_TOOL_CALLS=4 内）
- [ ] **C15 有界循环**：问一个需要反思改写的问题（如先给模糊查询 `有没有好吃的`，等它反问或给热销后，再补 `要辣的零食`）→ 全程不卡死、不无限循环（AGENT_MAX_STEPS=2 硬上限）
- [ ] **C16 幻觉抑制抽查**：C8/C10 的回答里，订单号、金额、物流节点是否与数据库真实值一致（抽 2 处对照小程序订单页）——工具数据是拼装注入的，模型不应改动数字

## 第 4 部分：多轮对话与会话记忆

- [ ] **D1 指代补全**（build_contextual_query 机制）：同一会话内先问 `有没有脐橙`，再问 `便宜点的` → 第二轮按"脐橙 便宜"召回，卡片是脐橙且价格低；不是把"便宜点的"单独拿去全库召回
- [ ] **D2 省略主语追问**：先问 `运费怎么算`，再问 `那生鲜的呢` → 能理解指代并答生鲜运费
- [ ] **D3 跨轮导购收窄**：`推荐点茶叶` → `要绿茶` → `100 以内的` → 卡片逐轮收窄且品类正确
- [ ] **D4 重启恢复**（checkpoints.db 持久化）：同一会话聊 2~3 轮后**重启 ai-service**（`docker compose restart ai-service`），回来问 `我刚才问了你什么？` → 记得上文（MEMORY_BACKEND=sqlite）
- [ ] **D5 新会话隔离**：新开一个聊天会话问 `继续刚才的话题` → 不应带上上一个会话的内容
- [ ] **D6 长会话稳定**：连续聊 20+ 轮（混合问政策/导购/订单）→ 不报错不白屏；极早期细节遗忘可接受（HISTORY_MAX_CHARS=3000 截断是设计行为），但最近几轮必须记得

## 第 5 部分：个性化推荐与语义搜索

- [ ] **E1 登录态推荐 feed**：用测试账号先浏览/收藏几个水果类商品，回首页看"为你推荐" → 出现推荐结果，每项有 `recommendReason` 可解释标签（如"和你浏览过的XX相关"）；多刷几次看排序是否稳定合理
- [ ] **E2 个性化生效对比**：换一个**没有行为记录**的账号看首页推荐 → 与 E1 的结果顺序不同（偏好项 α=0.25 类目偏好参与打分）
- [ ] **E3 游客回退**：退出登录看首页推荐 → 仍能出结果（游客不叠加偏好项，销量/好评/新鲜度项仍生效；AI 服务故障时应回退热销榜，见 G2）
- [ ] **E4 搜索框语义召回**：搜索框输入描述性词 `送礼的水果` → 出现语义召回结果（走 /v1/rec/search，0.35 闸门）
- [ ] **E5 搜索域外词回退**：搜索框输入 `手机` → 走全文检索回退，结果为空或无关，**不硬凑农产品**（搜索框 0.35 有全文退路，与对话侧 0.47 是两套闸门，各自都要测）
- [ ] **E6 冷启动合理性**：全新账号的推荐应主要来自销量（β=0.10）、好评率（γ=0.10，含 Bayesian 收缩）、上架新鲜度（δ=0.15），结果不荒诞

## 第 6 部分：管理后台 AI 功能闭环

- [ ] **F1 统计卡对账**：知识库页"FAQ 数"与 MySQL `ai_faq` 表 enabled 行数一致；"索引数"与 Chroma 一致；"商品索引数"与 Java 在售商品数差值可解释
- [ ] **F2 FAQ 新增 → 立即可问**：新增一条测试知识（如问：`你们支持货到付款吗？` 答：`目前仅支持在线支付。` 分类 platform），保存后**立即**去聊天页问同义句 → 能答出（保存即增量入索引，无需重建）
- [ ] **F3 FAQ 停用 → 立即失效**：把 F2 那条停用，再问同义句 → 命中不了（停用即索引除名）
- [ ] **F4 FAQ 编辑生效**：编辑某条答案里的关键数字（如客服工作时间），再问 → 答新口径
- [ ] **F5 FAQ 删除**：删除 F2 测试条目，列表消失
- [ ] **F6 重建 FAQ 索引按钮**：点"重建 FAQ 索引" → 返回成功、索引数刷新
- [ ] **F7 重建商品索引按钮**：点"重建商品索引" → 商品索引数与在售商品数对齐
- [ ] **F8 运营卡数据**：测到现在为止"对话量 > 0、拒答率有值、工具分布与实际调用相符、按日趋势图有数据"
- [ ] **F9 命中 Top**：状态卡"近 7 日命中 Top"出现你刚测过的那些问题（kb_hits.db 记录）
- [ ] **F10 工单闭环**：C12 产生的工单在列表可见、可筛选、处理后状态正确、显示处理人
- [ ] **F11 评价 AI 能力**：评价管理页选一条差评点"AI 生成回复草稿" → 草稿是道歉+补偿话术；好评 → 感谢话术；中评 → 改进话术；点"口碑分析同步" → 未分析评价被批量打标；仪表盘出现情感分布饼图
- [ ] **F12 权限**：OPERATOR 角色登录后台 → 访问 `ai/kb` 被拦截

## 第 7 部分：健壮性与降级（工程容错）

> 降级路径都是设计行为（fail-safe），预期是"友好话术"而不是报错堆栈。

- [ ] **G1 SSE 流式链路**：聊天页发消息 → 逐字打字机渲染；浏览器 DevTools Network 里 `chat/stream` 的 EventStream 事件顺序为 `status → token(多条) → items(有卡片时) → done`（或 `error`）
- [ ] **G2 AI 服务停机**：`docker compose stop ai-service` 后：①首页推荐仍出（回退热销榜）②聊天给出友好提示不白屏 ③搜索框退回 MySQL 全文检索。测完 `start` 恢复
- [ ] **G3 内部密钥错误**：直连 Python 带错 `X-Internal-Key` → 401；Java 侧内部接口被 `AiInternalAuthInterceptor` 拒（fail-closed，不静默放行）
- [ ] **G4 LLM 故障降级**：临时把 `ai-service/.env` 的 `AGNES_API_KEY` 改错并重启 → 聊天返回降级话术（不裸抛异常）；恢复后正常
- [ ] **G5 工具取数故障**：停掉 Java 后端只留 ai-service，问 `我的订单` → 友好降级话术，日志出现 WARNING，用户侧无堆栈
- [ ] **G6 未登录业务工具**：C9 已测，此处确认降级话术里出现客服电话且不泄露内部细节
- [ ] **G7 重排器回退**：把 `data/reranker` 目录临时改名重启 → 检索仍可用（回退融合序，日志 WARNING）；改回恢复
- [ ] **G8 会话维护**：确认 checkpoints.db 存在且 `CHECKPOINT_TTL_DAYS=7` 清理任务在启动时执行无报错（日志）
